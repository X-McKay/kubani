We're building autonomous AI agents within the kubani monorepo using a Temporal-orchestrated architecture. Each agent is a Python package that defines workflows (orchestration logic - what steps to execute) and activities (implementation - the actual work like API calls, LLM inference, database writes). Agents run as Temporal workers deployed in Kubernetes pods that poll the existing Temporal server for tasks. This provides durable execution with automatic retries, state management, and workflow history.

Agents leverage the existing infrastructure: vLLM endpoints for local LLM inference (OpenAI-compatible API), PostgreSQL for data persistence, and the Strands SDK for agentic reasoning with Model Context Protocol (MCP) servers providing structured tool access. Activities can contain Strands agents that use MCP tools to interact with systems like Kubernetes APIs, RSS feeds, or databases. Workflows compose these activities into multi-step processes like "fetch news → summarize with LLM → post to Discord" with built-in scheduling, error handling, and observability.

The repository structure keeps agents isolated: each agent lives in agents/{agent_name}/ with its own pyproject.toml for dependencies, Dockerfile for containerization, and test suite. A shared agent_platform/ package provides common utilities like vLLM client wrappers and Temporal helpers. Agents deploy via GitOps (Flux) with manifests in gitops/apps/ai-agents/ and can output to multiple channels: PostgreSQL for historical data, Discord/Slack for notifications, GitHub PRs for actionable changes, or Temporal query results for programmatic access. This design ensures each agent is independently testable, deployable, and maintainable while sharing infrastructure.
