# DB Admin Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Root owns integration and live operations; Sol workers own narrow isolated tasks.

**Goal:** Deploy a read-only DB Admin agent through agentgateway and preserve an honest account of deployment friction.
**Architecture:** Fixed agent diagnostics call a dedicated restricted PostgreSQL MCP backend. Database functions expose bounded operational summaries through a non-admin login.
**Tech Stack:** Python/Zetra SDK, PostgreSQL, Crystal DBA MCP, Kubernetes/Flux, Keycloak, private Sigstore.
**Spec:** ../specs/2026-11-06-db-admin-design.md

## Global Constraints

Preserve existing checkouts and paused qualification work. SOPS-only credentials, no secret output or Pod secret reads. No rollout restart, engine/broker outage, or concurrent agent tags. Signature, all five attestations and NoDrift precede a separate AgentRelease approval.

## Review Focus

- SQL diagnostics never expose application rows or raw query text.
- Database errors, missing fields, oversize results and partial collection never imply healthy status.
- Gateway JWT, external authorization and tool restrictions cover the new route.
- SQL bootstrap remains idempotent and never broadens the MCP login to pg_monitor/admin.
- Packaged source, manifests, grants and policy digests agree; real session proves transport.
