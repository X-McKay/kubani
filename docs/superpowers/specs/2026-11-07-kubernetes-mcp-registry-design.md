# Kubernetes MCP referenced registration design

## Approved outcome

Register the deployed Kubernetes MCP backend for generic preflight and standard identity descriptors, without transferring GitOps ownership or changing any effective runtime object. Add `existing-streamable-http-v1`; retain `container-sse-v1` unchanged. The existing Kubernetes server image tag is preserved; this work makes no new digest-pin claim. No Secrets, SQL, bootstrap, provisioning, realm/sourceRealm extensions, workload restart, image update, gateway update or network update.

## Declaration and immutable review binding

Create `infrastructure/mcp/backends/kubernetes.yaml` with exact fields `version: 1`, `name: kubernetes`, `profile: existing-streamable-http-v1`, `workload`, `authorization`, `secrets: []`, `upstreams: []`, `references`, and `externalReferences`. Reject bootstrap/provision on this profile. `workload` has exactly `namespace: mcp`, `service: kubernetes-mcp`, `port: 8080`, `path: /mcp`, `protocol: StreamableHTTP`. Authorization retains `agent-role-kubernetes-read`, the ordered exact tools `events_list`, `pods_get`, `pods_list_in_namespace`, `pods_log`, `resources_get`, `resources_list`, plus a reviewed nonempty scopeDescription.

Each `references` item has exactly `path`, `apiVersion`, `kind`, `namespace`, `name`, `canonicalSHA256`. Namespace is the empty string for cluster-scoped objects. Hash format is `sha256:<64 lowercase hex>`, calculated over `json.dumps(object, sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False).encode("utf-8")`, with no trailing newline. Hash the selected complete source object, never an entire multi-document file. YAML duplicate keys, invalid/nonpublic kinds, duplicate selected identities across references, missing or ambiguous selected documents, symlink paths, unsafe paths and hash mismatch fail closed. Bound reference counts and source size. Use `model.safe_path` and `yaml_documents`; do not expose source bodies in errors.

Freeze all six identities from `infrastructure/gitops/apps/mcp/kubernetes-mcp.yaml`: ServiceAccount `mcp/kubernetes-mcp`, ClusterRoleBinding `/mcp-kubernetes-mcp-view`, ConfigMap `mcp/kubernetes-mcp-config`, Deployment `mcp/kubernetes-mcp`, Service `mcp/kubernetes-mcp`, NetworkPolicy `mcp/allow-kubernetes-mcp-apiserver-egress`. Require that this workload file contains exactly this complete identity set, so newly added documents cannot silently broaden it.

Freeze four identities in namespace ai-gateway: AgentgatewayBackend `agents-mcp-kubernetes` from `agents/backends.yaml`, HTTPRoute `agents-mcp-kubernetes` from `agents/routes.yaml`, AgentgatewayPolicy `agents-extauth-mcp-kubernetes` from `agents/policies-extauth.yaml`, AgentgatewayPolicy `agents-mcp-kubernetes-tools` from `agents/policies-mcp-tools.yaml`; all four paths are under `infrastructure/gitops/apps/ai-gateway/`. Other backends in those shared files remain independent, subject to existing complete validation. Require exactly this reviewed ten-object reference identity/path set for the bounded profile. Validate Service selector/port resolves to the capture container on 8080, backend is /mcp StreamableHTTP, route and extAuth binding match kubernetes, exact tool policy is the frozen existing expression, and service account/binding target is built-in view.

`externalReferences` contains exactly one reference with the same six fields, pointing to `infrastructure/mcp/baseline/kubernetes-view.json`, identity `rbac.authorization.k8s.io/v1`, `ClusterRole`, empty namespace, `view`. The snapshot contains only apiVersion, kind, metadata.name, rules and aggregationRule, projected from root's `/tmp/kubernetes-mcp-evidence/view-before.json`. Hash that projection by the same canonical algorithm. It is a reviewed external dependency for status, never generated or included in Kustomize/apply output. Status compares live rules and aggregationRule exactly after the same projection; aggregated additions must report drift. Offline validation verifies the snapshot/hash and its role linkage, without pretending the external role is in GitOps.

## Rendering, checking and status interfaces

Introduce `model.canonical_sha256(document) -> str` and `model.referenced_objects(root, entry, *, external=False) -> list[dict]`, which enforce references and return selected objects. New profile validation calls these functions and enforces the bounded contract. Existing identity `descriptor(entry)` remains unchanged.

Separate generated ownership from registration expectations. `render._backend_objects` returns generated objects only for SSE and no generated runtime objects for the referenced profile. Add `render._registration_objects(root, entry) -> list[dict]`: generated objects for SSE, selected source references for the new profile. Generated inventory `objects` continues to mean generated ownership; record reviewed reference metadata under the new backend inventory record, never under owned files/objects. Descriptor generation includes kubernetes normally.

Only generated SSE entries extend shared-auth target patches, managed-route ownership checks and human gateway exclusion values. Kubernetes already has shared-auth coverage in handwritten policies and baseline: preserve those files/baselines byte-for-byte and require the original exact baseline plus generated SSE targets. Source/generated collision protection stays strict for generated objects. Referenced objects must have exactly one matching identity in the effective complete Kustomize build and equal the frozen source object. Effective additive NetworkPolicy baseline remains unchanged; Kubernetes API egress is already in it. No new ingress is needed: agents access already exists, including `netpol/upstreams.yaml`.

`render.objects` returns complete registration expectations: ten selected Kubernetes source objects, status-only external view snapshot, shared auth and existing shared effective network paths (deduplicated by identity). It must retain all applicable shared ingress/egress and DNS policies and Kubernetes-specific API egress. Root's RBAC implementer owns `status.py` and CLI KubeReader changes: add ServiceAccount, ClusterRoleBinding, ClusterRole status handling and exact cluster-scoped reads; expose no apply path. External view comparison projects only the five reviewed fields. Keep status `functional: not-tested`.

## Evidence and rejection cases

Before/after complete Kustomize object maps must be identical; generated postgres-admin runtime and descriptor bytes remain identical. Permitted changes: new declaration/snapshot/descriptor, registry inventory adding backend/reference metadata and descriptor file hash, implementation/tests/docs. Existing generated YAML, shared-auth patches, human exclusions, source manifests and baseline JSON remain identical. Test rejected source mutations to pod image/sidecar/config/RBAC/API egress/gateway/tool/extAuth, missing/duplicate/excluded objects, added workload documents, unsafe references, malformed schema/hash, external role drift and permission-increasing role changes. Tests must not read live cluster, secrets or network.
