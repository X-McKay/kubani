# Operator T10a contract gate

`conformance-delegation-contract.py` exercises the revision 3 contract in spec
7.5: requesting client = actor client; both client assertion and actor access
token are genuine. The older A/B alternatives in the test table are withdrawn
by revision 3. The ordinary `agent-conformance` CLI does not implement T10a;
passing `--tests T10a` is not a substitute for this gate.

Root owns live operations. Use the current approved, signed conformance release
to start and hold an ordinary session sandbox, plus one conformance-b sandbox
for the wrong-actor variant. Record their exact Running Pod names and UIDs.
Do not create a debug Pod or read any Pod's credentials. Finish other exclusive
qualification batches before starting these sessions. Afterward cancel/complete
both sessions through the ordinary runner and confirm sandbox/grant cleanup.
This operator never creates a sandbox or grant and cannot clean up sessions it
did not create.

The operator requires local Python with PyYAML and PyJWT[crypto], sops, kubectl,
`KUBECONFIG=/home/al/.kube/config`, and the existing age key. It reads the local
SOPS bootstrap administrator credential only for identity/configuration reads.
It makes Kubernetes TokenRequests, bound to the exact Pod UID with the issuer
audience and 300-second lifetime. Tokens remain in memory; neither stdin request
payloads nor subprocess output is logged. It authenticates the real actor using
that assertion, and uses the same assertion for the delegated exchange.

Prepare positive Alice consent with the reviewed `conformance-delegation.py
--mint` helper. Prepare the ordinary wrong-consent Alice fixture with the existing
human-token helper, immediately before the run; its `stringData.token` format is
accepted as well as `stringData.access_token`. Positive fixtures with genuine
refresh tokens are refreshed if needed, and any rotated credentials are written
back only through SOPS. An expired fixture without refresh is an error.

No authentic other-tenant human fixture currently exists in this repository.
The gate explicitly fails that missing-evidence check. Do not edit a JWT, reuse
Alice as another user, create a new user, or grant another principal to satisfy
it. A future separately reviewed fixture must have a distinct subject and signed
`tenant` provenance; provide its SOPS file, subject and other tenant together.
Absent signed tenant provenance, another subject is insufficient evidence for
the spec's other-tenant variant.

Example root invocation, with exact reviewed input paths and recorded Pod IDs:

```sh
export SOPS_AGE_KEY_FILE=/home/al/git/kubani/age.key
python infrastructure/scripts/ops/conformance-delegation-contract.py \
  --subject /tmp/runtime-resume-evidence/alice-conformance.enc.yaml \
  --wrong-consent /tmp/runtime-resume-evidence/alice-ordinary.enc.yaml \
  --pod CONFORMANCE_POD --pod-uid CONFORMANCE_UID \
  --wrong-actor-pod CONFORMANCE_B_POD --wrong-actor-pod-uid CONFORMANCE_B_UID \
  --realm-export /tmp/runtime-resume-evidence/agents-t10a-realm.enc.yaml \
  > /tmp/runtime-resume-evidence/t10a-report.json
```

The read-only partial realm export is encrypted directly through SOPS, including
any client configuration secrets. The report contains only the encrypted file's
path/hash, never export contents. Retain this authoritative export privately;
do not commit it without reviewing its scope. Omit `--realm-export` for an
exploratory run; that run cannot qualify T10a.

The positive JWT is verified against the issuer JWKS, issuer, expiry and required
claims. The report records the exact `sub`, `act`, `aud`, `azp`, `scope` and times;
it excludes JWTs, assertion contents, cookies, passwords and refresh tokens.
Checks require Alice's subject, exact actor attribution, exactly the Kubernetes
resource audience, actor authorized party and exactly `mcp:kubernetes` scope.
An audience that does not narrow is reported as a failed check, with the actual
safe claim values available for contract review; it is never silently accepted.

Wrong-consent uses the genuine ordinary Alice JWT. Wrong-actor authenticates a
genuine conformance-b actor against the original Alice consent. Wrong-audience
adds an unavailable resource audience to the otherwise valid exchange. Wrong-user
uses the separately verified other-tenant human JWT. Each case must receive an
actual IdP OAuth 4xx refusal; local validation errors, transport failures, unknown
errors and 5xx responses are not evidence of refusal. Missing fixtures and a
missing realm export make `qualified=false` and the process exit nonzero.
No live evidence is claimed by unit tests or by preparing these files.

Review corrections: every wrong variant now obtains fresh actor authentication
and is bracketed by real, claim-checked positive delegated exchanges. Both
subject and actor tokens must still have at least 30 seconds of verified life;
the API-returned Pod-bound assertion must have at least 60 seconds at issuance
and 30 seconds immediately before exchange. A failed positive control prevents
sending/counting that variant. Generic OAuth 4xx, invalid client authentication,
expired/invalid subject or actor tokens, rate limits and unclassified errors
cannot pass. Only exact pinned 26.8.1 status/error/description tuples map to fixed
safe refusal enums. For the intentionally unavailable audience, the pinned
`invalid_client` / `Audience not found` branch is admitted specifically; other
`invalid_client` errors never count. Raw descriptions remain unreported.

Actor provenance checks join the root-supplied Pod UID to the deterministic real
session UUID/generation/name and an approved, signature-verified Ready/no-drift
AgentRelease plus its controller-owned Pod template. Container/init-container
shape, pinned images, runtime, service account, session environment and policy
annotations must match that template (server scalar defaults may be added).
The Pod is re-read after authentication. The TokenRequest response is checked
against the exact namespace/service account/issuer audience/Pod name+UID and
expiry before using it for real IdP authentication; this check reads only the
trusted API response in memory, and a successful IdP client-auth exchange verifies
the actual assertion. No credential is put in argv, logs, history or reports.
Reports retain only safe release/template/Pod identity and expiry provenance.
Root must also retain the ordinary SessionWorkflow start/run receipts joined to
the reported session UUID; this operator does not query Temporal history or
claim that Kubernetes labels alone prove workflow origin.

The other-tenant case remains incomplete until separately approved authentic
fixture provenance exists. Do not grant that user delegation merely to create
a matching consent token: the expected restriction is the exact user-specific
FGAP `delegate` permission, which may deny issuance of `may_act` itself. Record
that mechanism; do not claim an independent tenant-claim matcher. A potential
future fixture is unprivileged `conformance-bob-tenant-other`, using agent-cli
PKCE and admin-controlled signed `tenant=tenant-other`, with no delegate,
backend or admin roles. User/client-scope/mapper creation needs its own approval.
